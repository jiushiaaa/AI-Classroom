# PRD｜单页历史记录、版本预览与页面回收站 V1.1.0

## 1. 模块说明

单页历史记录用于记录 AI 课堂单页编辑过程中的关键版本，帮助用户在手动修改或 AI 优化后回看、预览和恢复当前页面的历史版本。

本功能服务于课堂编辑模式。用户在编辑当前课堂页面时，系统自动保存当前页版本；用户可从顶部工具栏进入“第 X 页历史记录”面板，点击某一条历史记录后进入历史版本预览态。预览态只展示该版本内容，不直接覆盖当前页面。只有用户明确点击“还原此历史记录”并在二次确认弹窗中确认后，系统才将该历史版本恢复为当前正式版本。

若用户误删页面，系统不应立即物理删除该页面及其历史记录，而应将页面放入“页面回收站”。用户可从页面回收站恢复该页面，恢复后该页面的历史记录继续可用。

本模块的核心目标是降低用户编辑时的试错成本，让用户敢于使用 AI 优化和手动编辑，不担心改坏页面后无法回退。

---

## 2. 背景与问题

当前 AI 课堂编辑模式已经支持手动修改、撤销、重做和 AI 优化。但撤销 / 重做更偏向短期编辑操作，不适合解决以下问题：

| 问题 | 说明 |
| --- | --- |
| AI 优化后缺少可回看版本 | 用户使用 AI 优化后，希望查看之前生成过的不同结果 |
| 手动编辑缺少长期版本 | 用户编辑一段时间后，希望回到几分钟前或上一次保存的状态 |
| 撤销 / 重做不适合跨阶段回退 | 用户关闭页面、切换页面或完成多步编辑后，撤销链路不稳定 |
| 用户担心误操作 | 没有清晰历史版本时，用户不敢大胆修改或多次尝试 AI 优化 |

因此需要一个独立的“第 X 页历史记录”能力，覆盖当前页的 AI 优化版本和手动修改版本；同时需要页面回收站兜底误删场景，避免页面删除后历史记录入口随页面一起消失。

---

## 3. 用户价值

| 用户 | 价值 |
| --- | --- |
| 出版社编辑 | 修改教辅课堂时可放心试错，快速恢复之前版本 |
| 教研老师 | 多次调整讲解内容或页面布局后，可对比不同阶段结果 |
| 销售 / 交付人员 | 演示 AI 优化能力时，可展示修改前后的效果，并安全还原 |
| 内部产品 / 研发 / QA | 有明确版本链路，便于复现编辑过程中的内容变化 |

## 4. 功能范围

### 4.1 本期覆盖

| 能力 | 说明 |
| --- | --- |
| 顶部历史记录入口 | 在顶部标题旁、撤销 / 重做附近展示历史记录 icon；tooltip 与面板标题使用“第 X 页历史记录”；slide、quiz、PBL 等页面均需展示 |
| 保存状态展示 | 在历史记录 icon 右侧展示“保存中...”和“已保存”状态 |
| 自动保存版本 | 手动编辑后自动保存为历史版本 |
| AI 优化版本记录 | 每次 AI 优化完成后保存为历史版本 |
| 历史记录侧边栏 | 点击历史 icon 后，在顶部工具栏下方展示当前页历史记录面板 |
| 历史版本预览 | 点击历史记录后，主画布进入该版本的预览态 |

| 返回当前版本 | 用户可退出历史预览，回到当前正式版本 |
| 页面回收站 | 删除页面后保留页面数据和历史记录，用户可恢复误删页面 |

### 4.2 本期不覆盖

| 不覆盖内容 | 说明 |
| --- | --- |
| 多人协作记录 | 当前非团队版，不展示操作者、协作者头像或多人编辑轨迹 |
| 版本差异对比 | 不做逐字 diff、高亮新增 / 删除内容 |
| 审批流 | 不涉及版本审批、发布审核、回滚审批 |
| 云端多端冲突处理 | 本期只定义单用户编辑场景 |
| 全课堂一键恢复 | 本期以单页版本和页面回收站为主，不做整套课堂全局版本恢复 |

## 5. 入口与布局

### 5.1 顶部工具栏入口

历史记录入口放在顶部标题旁边，与撤销、重做处于同一组编辑变更管理区域。入口不应被居中工具栏挤到页面中部，也不应只在 slide 页面展示。为避免用户误解为全局课堂历史，入口 tooltip 和面板标题必须使用“第 X 页历史记录”。

| 元素 | 说明 |
| --- | --- |
| 撤销 | 回退短期编辑操作 |
| 重做 | 恢复被撤销的短期操作 |
| 历史记录 icon | 点击打开当前页历史记录面板 |
| 保存状态 | 展示在历史记录 icon 右侧，文案为“保存中...”或“已保存” |

推荐排列顺序：

> 返回 / 课堂标题 / 撤销 / 重做 / 历史记录 icon / 保存状态

不同页面类型的展示规则：

| 页面类型 | 是否展示当前页历史记录 | 说明 |
| --- | --- | --- |
| slide | 展示 | 与撤销、重做、插入工具共存 |
| quiz | 展示 | 即使不能手动编辑，也需要查看 AI 优化或结构变化历史 |
| PBL | 展示 | 即使不能手动编辑，也需要查看 AI 优化或项目内容变化历史 |
| interactive | 展示 | 若页面存在 AI 调优或内容更新，需保留历史入口 |
| 学生预览 / 只读模式 | 不展示 | 避免影响学生端体验 |

放置原因：

1. 撤销、重做、保存状态、单页历史记录都属于编辑变更管理。
2. 用户编辑时会自然关注页面标题和顶部工具栏左侧。
3. 与右侧笔记区、左侧页面缩略图区职责清晰，不抢占内容编辑空间。
4. quiz / PBL 虽然不走 PPTist 手动编辑工具，但仍可能被 AI 优化或恢复版本，因此历史入口不能依赖 slide 插入工具是否展示。

### 5.2 当前页历史记录面板位置

当前页历史记录面板应显示在顶部工具栏下方，与右侧笔记区同高。

| 场景 | 面板位置 |
| --- | --- |
| 右侧笔记区展开 | 当前页历史记录面板停靠在笔记区左侧，不覆盖笔记 |
| 右侧笔记区收起 | 当前页历史记录面板停靠在页面右侧 |
| 多端预览模式 | 默认不展示历史记录入口，避免影响学生预览体验 |

### 5.3 视觉风格

当前页历史记录面板应与右侧笔记区保持一致，避免独立弹窗感。

| 视觉项 | 要求 |
| --- | --- |
| 面板高度 | 从顶部工具栏下方开始，到页面底部结束 |
| 背景 | 白色或浅灰背景，与右侧笔记一致 |
| 卡片 | 使用轻量卡片，不使用强阴影或大面积高饱和色 |
| 当前版本 | 使用浅紫色背景或轻量标签标识 |
| 操作者 | 当前版本不展示操作者姓名 |
| 底部开关 | 不展示“显示更改”开关 |

## 6. 历史记录内容

### 6.1 列表分组

历史记录按时间分组展示。

| 分组 | 规则 |
| --- | --- |
| 今天 | 当天生成的版本 |
| 本周 | 最近 7 天内但非当天的版本 |
| 上周 | 7-14 天内的版本 |
| 更早 | 超过 14 天的版本 |

若产品实现阶段暂不区分“今天”，可先展示“本周 / 上周 / 更早”，但需保留扩展能力。

### 6.2 单条历史记录字段

| 字段 | 是否展示 | 说明 |
| --- | --- | --- |
| 时间 | 展示 | 如“5月18日 11:49” |
| 最近更新 | 展示 | 当前最新版本显示 |
| 最新版本 / 预览中 | 展示 | 最新正式版本或当前正在预览的版本 |
| 来源 icon + 来源文字 | 展示 | 如“手动修改”“AI 优化”“还原自 5月18日 11:28 的版本” |
| 操作者 | 不展示 | 当前非团队版，不显示“少华”等人员信息 |
| 版本说明正文 | 不展示 | 不展示卡片中间的“手动修改”等重复文案 |

### 6.3 来源类型

| 来源 | 展示文案 | 触发方式 |
| --- | --- | --- |
| 手动修改 | 手动修改 | 用户编辑页面内容后自动保存 |
| AI 优化 | AI 优化 | 用户通过 AI 优化页面或笔记后保存 |
| 还原记录 | 还原自 {{versionTime}} 的版本 | 用户确认还原某条历史记录后生成 |

## 7. 保存规则

### 7.1 自动保存状态

顶部工具栏展示保存状态。保存状态必须位于历史记录 icon 右侧，不能插在撤销 / 重做与历史记录 icon 中间。

| 状态 | 展示文案 | 说明 |
| --- | --- | --- |
| 保存中 | 保存中... | 用户修改后，系统正在生成版本并保存 |
| 已保存 | 已保存 | 当前修改已保存为版本 |
| 默认 | 不展示 | 无新修改或状态已过期 |
| 保存失败 | 保存失败 | 可作为后续扩展，本期可不展示 |

### 7.2 手动修改保存规则

用户手动修改当前页面后，系统自动保存历史版本。

| 规则 | 说明 |
| --- | --- |
| 延迟保存 | 用户停止操作一段时间后自动保存，建议 2-5 秒 |
| 合并连续修改 | 连续输入、拖拽、调整样式应合并为一个版本 |
| 不重复保存 | 若内容与上一版本完全一致，不新增版本 |
| 切换页面 | 切换页面前应确保当前页面修改被保存 |
| 退出编辑 | 退出编辑前应确保当前页面修改被保存 |

### 7.3 AI 优化保存规则

| 场景 | 保存规则 |
| --- | --- |
| AI 优化成功 | 立即保存一个历史版本 |
| AI 优化失败 | 不生成历史版本 |
| AI 优化多次 | 每次成功结果单独生成版本 |
| AI 优化后继续手动编辑 | 手动编辑在延迟保存后生成新的手动版本 |

## 8. 历史预览规则

### 8.1 进入历史预览

用户点击某条历史记录后，进入该版本预览态。

进入预览态后：

1. 主画布展示该历史版本的内容。
2. 当前页历史记录面板中该条记录显示“预览中”。
3. 顶部出现历史预览工具条。
4. 当前正式版本不被覆盖。
5. 自动保存暂停，避免把预览内容误保存成新版本。

### 8.2 历史预览工具条

进入预览态后，顶部工具栏下方或顶部区域展示历史预览工具条。

| 元素 | 说明 |
| --- | --- |
| 返回当前版本 | 退出历史预览，回到当前正式版本 |
| 还原此历史记录 | 将当前预览版本恢复为正式版本 |
| 编辑记录序号 | 如“编辑记录 1/3” |
| 上一项 | 预览上一条历史记录 |
| 下一项 | 预览下一条历史记录 |

### 8.3 预览态限制

| 限制 | 说明 |
| --- | --- |
| 不允许直接编辑 | 预览态下不允许修改画布内容 |
| 不自动保存 | 预览态不触发自动保存 |
| 不改变正式版本 | 只有确认还原后才改变当前页面 |
| 退出后恢复 | 点击返回当前版本、关闭历史面板、切换页面时，退出预览态 |

### 8.4 上一项 / 下一项

| 操作 | 说明 |
| --- | --- |
| 上一项 | 预览时间上更近的一条历史记录 |
| 下一项 | 预览时间上更早的一条历史记录 |
| 第一条 | 上一项置灰 |
| 最后一条 | 下一项置灰 |

## 9. 还原规则

### 9.1 还原入口

用户进入历史预览后，可点击“还原此历史记录”。

### 9.2 还原行为

用户点击“还原此历史记录”后，系统先弹出二次确认。用户在二次确认中点击“还原”后，系统执行：

1. 将预览版本内容覆盖为当前页面正式内容。
2. 生成一条新的历史版本，来源展示为“还原自 {{versionTime}} 的版本”。
3. 退出历史预览态。
4. 当前页面展示恢复后的正式内容。
5. 顶部保存状态展示“已保存”或进入保存中状态后变为“已保存”。

### 9.3 二次确认

点击“还原此历史记录”后必须展示二次确认弹窗，避免用户误还原。

| 弹窗元素 | 文案 / 规则 |
| --- | --- |
| 标题 | 还原此记录? |
| 说明 | 将当前页面还原至 {{versionTime}} 的状态 |
| 取消按钮 | 取消，点击后关闭弹窗，不执行还原 |
| 确认按钮 | 还原，点击后执行还原 |

弹窗出现时，历史记录面板和主画布可被遮罩弱化，用户必须先处理弹窗。

## 10. 页面删除与回收站

### 10.1 为什么不做整课还原

历史版本恢复应以单页为主，不建议默认提供整课全部还原。

| 方案 | 问题 |
| --- | --- |
| 整课还原 | 用户只想恢复某一页时，会把其他页面近期修改一起回滚 |
| 单页还原 | 更符合“只恢复当前页”的编辑心智，但需要处理页面被删除后的恢复入口 |

因此本期采用“单页历史记录 + 页面回收站”方案。

### 10.2 页面删除规则

用户删除页面时，系统执行软删除，不立即物理删除页面数据。

| 规则 | 说明 |
| --- | --- |
| 从左侧页面列表移除 | 删除后该页不再作为正常页面展示 |
| 保留页面快照 | 页面标题、类型、内容、讲稿、历史版本仍需保留 |
| 记录删除时间 | 记录 deletedAt，用于回收站排序和展示 |
| 记录删除时间 | 记录 deletedAt，用于回收站排序和后续清理 |
| 不清空历史版本 | deleted 页面上的 versions 必须保留 |

### 10.3 页面回收站入口

左侧页面栏底部固定展示“回收站”icon。回收站属于页面管理能力，不参与页面排序，不应直接铺在缩略图列表中，以免干扰用户浏览当前课堂页面。

| 字段 / 操作 | 说明 |
| --- | --- |
| 回收站 icon | 放在左侧页面栏底部，hover 显示“回收站” |
| 状态提示 | 当存在已删除页面时，icon 可显示轻量提示点 |
| 弹层 | 点击 icon 后打开回收站列表 |
| 页面标题 | 展示删除前页面标题 |
| 页面状态 | 展示“已删除页面”，不展示“原第 X 页” |
| 更多操作 | 使用“···”触发更多菜单 |
| 恢复 | 更多菜单操作，将页面恢复到课堂中 |
| 彻底删除 | 更多菜单操作，从回收站永久移除该页面及其历史 |

页面回收站不替代历史记录。它只解决“页面本身被误删后如何找回”的问题。

### 10.4 恢复页面规则

用户点击“恢复此页面”后，系统执行：

1. 将该页面从页面回收站移回正常页面列表。
2. 恢复位置可优先按删除前位置插入；若连续删除导致原页码表达不稳定，前端不展示原页码。
3. 恢复后重新计算页面顺序。
4. 当前选中页切换为恢复后的页面。
5. 保留该页面原有历史版本，用户可继续进入“第 X 页历史记录”查看和还原版本。

### 10.5 后续可扩展

| 能力 | 说明 |
| --- | --- |
| 彻底删除 | 用户手动清空回收站或删除某条已删除页面 |
| 保留期限 | 超过 N 天自动清理已删除页面 |
| 删除前预览 | 在回收站中预览删除前页面内容 |
| 恢复位置选择 | 恢复时允许选择插入到当前页之后或课程末尾 |

## 11. 状态与边界

### 11.1 空状态

当当前页无历史版本时，历史记录面板展示空状态。

推荐文案：

> 暂无历史记录。手动编辑或 AI 优化后会自动保存版本。

### 11.2 保存中点击历史记录

| 场景 | 处理 |
| --- | --- |
| 保存中打开历史记录 | 可以打开，但最新修改可能尚未出现在列表 |
| 保存中点击历史记录 | 若当前修改尚未保存，需先完成保存或提示“当前修改保存中” |
| 保存失败 | 保留当前编辑内容，提示用户稍后重试 |

### 11.3 预览中发生页面切换

用户在历史预览态切换左侧页面时：

1. 自动退出历史预览态。
2. 打开目标页面的正式版本。
3. 不保存当前预览内容。

### 11.4 预览中关闭历史面板

关闭历史面板时：

1. 自动退出历史预览态。
2. 主画布恢复当前正式版本。
3. 不生成新历史版本。

### 11.5 当前版本被恢复

若用户正在预览的版本就是当前最新版本：

1. 可以展示“最新版本”。
2. “还原此历史记录”可置灰或隐藏，也可允许还原但不产生内容变化。
3. 用户点击该条记录时仍可进入预览态，但不产生内容变化。

## 12. 数据记录要求

每个历史版本至少应记录以下信息。

| 字段 | 说明 |
| --- | --- |
| versionId | 版本唯一 ID |
| sceneId | 所属页面 ID |
| timestamp | 版本生成时间 |
| source | 来源：manual / ai / restore |
| title | 页面标题 |
| contentSnapshot | 页面内容快照 |
| noteSnapshot | 当前页笔记 / 讲稿快照，如与页面内容分开存储则需单独记录 |
| aiInstruction | AI 优化指令，仅 AI 来源版本需要 |
| summary | 版本摘要，可选 |
| signature | 内容签名，用于判断是否重复保存 |
| restoredFromTimestamp | 还原来源版本的时间戳，仅 restore 来源版本需要 |
| deletedAt | 页面被删除时间，仅删除页面需要 |
| deletedOrder | 页面删除前的位置，可用于恢复插入；前端不直接展示 |

当前非团队版不要求记录或展示操作者。若底层为了未来扩展保留 author 字段，前端本期不展示。

## 14. 验收标准

### 14.1 基础入口

1. 在编辑模式顶部标题旁、撤销 / 重做附近可看到历史记录 icon。
2. 点击历史记录 icon 后，面板从顶部工具栏下方打开。
3. 面板高度与右侧笔记区一致。
4. 右侧笔记区展开时，当前页历史记录面板不覆盖笔记。
5. quiz / PBL 等不能手动编辑的页面也应展示历史记录 icon。
6. 历史记录 icon 应贴近标题和撤销 / 重做区域，不得被推到顶部工具栏中间。
7. “保存中...”和“已保存”必须显示在历史记录 icon 右侧。
8. tooltip 与面板标题应显示“第 X 页历史记录”，不得仅显示“本页历史记录”或“历史记录”。

### 14.2 自动保存

1. 用户修改当前页内容后，顶部显示“保存中...”。
2. 保存完成后显示“已保存”。
3. 历史记录中新增一条“手动修改”版本。
4. 连续快速编辑不会产生大量重复版本。
5. 内容没有变化时，不新增版本。

### 14.3 AI 优化版本

1. 用户完成一次 AI 优化后，历史记录新增“AI 优化”版本。
2. 多次 AI 优化成功后，应出现多条历史版本。
3. AI 优化失败不新增版本。

### 14.4 历史预览

1. 点击某条历史记录后，主画布展示该版本内容。
2. 被点击版本显示“预览中”。
3. 顶部显示历史预览工具条。
4. 预览态下不自动保存。
5. 关闭历史面板后，画布恢复当前正式版本。

### 14.5 还原历史

1. 点击“还原此历史记录”后，出现二次确认弹窗。
2. 点击弹窗“取消”后，不执行还原。
3. 点击弹窗“还原”后，当前页面正式内容变为预览版本内容。
4. 还原后新增一条“还原自 {{versionTime}} 的版本”历史记录。
5. 用户仍可通过历史记录回到还原前版本。

### 14.6 页面回收站

1. 删除页面后，该页从左侧正常页面列表移除。
2. 左侧页面栏底部展示回收站 icon，点击后打开回收站弹层。
3. 删除页面后，回收站弹层展示该页。
4. 回收站中显示页面标题，不显示“原第 X 页”。
5. 每条删除页面右侧展示“···”更多操作。
6. 点击“···”后可选择“恢复”或“彻底删除”。
7. 点击“恢复”后，该页回到正常页面列表。
8. 点击“彻底删除”后，该页从回收站移除，不再可恢复。
9. 恢复页面后，该页原有历史记录仍可查看。
10. 恢复某一页不会回滚其他页面的内容。
